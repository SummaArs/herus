# 02 — The Herus Wire Protocol

Revision 0.3 · normative · every byte count and timing here is generated by
`tools/budget.py` §8–§10 and re-asserted at compile time in `firmware/net/region.c`;
every rule P1–P7 is a test in `firmware/test/test_net.c` that can fail.

**Revision 0.3 carries two errata found by implementing this document** — E-P1 (§2)
and E-P2 (§3.1). Both were invariants the prose asserted and the specification
could not deliver. They are the reason this revision exists.

This document is the contract between two Cores. It is written to be
implementable without reading anything else, and to be *auditable* — every
length and timing here is produced by the calculator, not chosen by hand.

Companion documents: [00-HERUS-MASTER.md](00-HERUS-MASTER.md) for why,
[01-ALGEBRA.md](01-ALGEBRA.md) for the symbol algebra.

---

## 1. Design rules

These are the invariants an implementation must not break. Each one exists
because breaking it silently destroys a property the product claims.

| # | Rule | Breaking it costs |
|---|---|---|
| **P1** | Every meaning-carrying frame occupies **exactly the same airtime** (246.8 ms at SF9) | airtime becomes a side channel; a panic glyph is separable from a status report with a spectrum analyser |
| **P2** | No frame may exceed **400 ms** of dwell in any region profile | the device is illegal, discovered at certification |
| **P3** | Hypervectors are **never transmitted** — only symbol ids | 1280 bytes instead of 2; the whole protocol collapses |
| **P4** | Unknown role ids are **skipped, never rejected** | forward compatibility is lost and every change becomes a flag day |
| **P5** | Tier 0.5 uses a **stream cipher and no MAC**; every other tier uses AEAD | mixing them up either kills graceful decode or silently ships malleable authenticated traffic |
| **P6** | Addresses on air are **ephemeral**, derived per message | a stable id is a tracking beacon |
| **P7** | The **only** length-distinguishable tier is Tier 2 | see §4.4 — this is accepted, not hidden |

## 2. Frame ledger

```
  tier               addr body tag  total  SF  hdr/CRC        airtime   dwell
  Tier 0 glyph        2    24   8     34    9  explicit,on    246.8 ms  ok
  Tier 1 composed     2    24   8     34    9  explicit,on    246.8 ms  ok
  Tier 0.5 sketch     2    36   0     38    9  implicit,off   246.8 ms  ok
  Tier 2 voice        2   168   8    178    7  explicit,on    287.0 ms  ok
  SOS beacon          2    16  64     82    8  explicit,on    256.5 ms  ok
```

`budget.py` asserts `airtime(Tier0) == airtime(Tier0.5)`, and `firmware/net/region.c`
asserts the same thing at compile time. If either fires, P1 has regressed and the
build must fail.

> **ERRATUM E-P1, revision 0.3.** Revision 0.2 gave Tier 0.5 the same 34 *bytes*
> and asserted `len(Tier0) == len(Tier0.5)`. That assertion passed while the
> invariant it was named after was broken: Tier 0.5 runs implicit header with CRC
> off, which removes 20 + 16 bits from the symbol count, so 34 B costs **226.3 ms**
> against 246.8 ms. A 20.5 ms difference — visible to exactly the spectrum analyser
> P1 exists to defeat, and 8× the Beat guard window.
>
> P1 is a statement about airtime; bytes were only ever a proxy for it. At SF9 the
> payload symbol count is a step function, and 36–39 B of implicit-header CRC-less
> payload all land on 48 symbols. **Tier 0.5 is therefore 38 bytes: 2 address + 32
> sketch + 4 pad.** The pad is not waste — it is a sketch extension to 288 or 320
> bits that a later revision can spend at *zero* airtime cost, because the step
> does not move until 40 bytes. The pad must be keystream, not zeros: a constant
> tail at a fixed offset in every beacon is a fingerprint.

Tiers 0, 0.5 and 1 reach a common airtime by opposite routes: the AEAD tiers *grow*
their plaintext to 24 B, and Tier 0.5 spends its bytes on sketch and pad because it
has no MAC. The growth is not padding — it raises Tier 1 from 4 slots to **9**
(§3.3).

## 3. Frame formats

### 3.1 On air

```
 offset  size  field
   0      2    HEADER              ttl:2 | ephemeral address:14   (see E-P2 below)
   2     24    CIPHERTEXT          AEAD, or 36 B keystream-XOR for Tier 0.5
  26      8    TAG                 ChaCha20-Poly1305, truncated to 64 bits
                                   (absent in Tier 0.5, whose body is 36 B)
 total   34    (38 for Tier 0.5 — same airtime, see E-P1)
```

> **ERRATUM E-P2, revision 0.3.** §3.2 placed `ttl` in the plaintext header and
> §5.2 had each relay decrement it and dedup on `(ephemeral_addr, seq)`. Those
> statements cannot both hold: the plaintext is inside the end-to-end AEAD, so a
> relay can read neither `ttl` nor `seq`. **As written, Weave was not
> implementable.**
>
> The fix spends two bits of the on-air address, because P1 leaves no spare byte:
>
> ```
>  bits 15..14  ttl       public, mutable, NOT authenticated
>  bits 13..0   address   public, authenticated (it is the AEAD's AAD, with the
>                         ttl bits cleared so both ends compute the same value)
> ```
>
> - Address space drops from 65536 to 16384; collisions get 4× more likely, which
>   §4.3 already declares acceptable and even useful. The cost is one wasted
>   decrypt attempt, bounded by the rate limiter.
> - `ttl` is malleable. Raising it cannot amplify a flood: dedup makes each node
>   forward a given frame at most once regardless of ttl. Lowering it suppresses
>   forwarding, which §10's threat model already concedes for a malicious relay and
>   which jamming achieves anyway.
> - Modifying the *address* bits breaks the tag. Verified in `test_net` P8.
> - Dedup keys on `FNV-1a(address with ttl masked ‖ ciphertext ‖ tag)`, which a
>   relay can compute. The tag is a 64-bit function of the whole message under a key
>   the relay does not have — a far better duplicate discriminator than a 16-bit
>   sequence number. Masking the ttl is essential: the same frame at ttl 3 and ttl 2
>   must be one fingerprint, or the flood never terminates.

Radio configuration, Tiers 0 / 1 / 2 / SOS:

| Parameter | Value |
|---|---|
| Modulation | LoRa, BW 125 kHz |
| Spreading factor | 9 (Tier 2: 7, SOS: 8) |
| Coding rate | 4/5 |
| Header | explicit |
| Payload CRC | **on** |
| Preamble | 8 symbols (32.8 ms at SF9 — see §6.2) |
| Sync word | private, never the LoRaWAN public word. **0x12** is the SX1276-era single-byte value, which is also what RadioLib's `setSyncWord()` takes; writing the SX126x registers directly (0x0740/0x0741) means writing **0x1424**. Both name the same thing — see `firmware/port/sx1262.c`. |

The truncated 64-bit tag gives 2⁻⁶⁴ forgery probability per attempt. That is
adequate only with a receive-side rate limit: **cap decrypt attempts per session
per second**, or the truncation becomes a real weakness rather than a byte saving.

### 3.2 Plaintext, common header

```
 byte 0   ver:2 | tier:3 | flags:3
 byte 1   ttl:4 | prio:2 | rsv:2      <- ttl here is the SENDER's initial value,
                                         advisory only; the authoritative hop
                                         counter is on air (E-P2). rsv must be 0.
 bytes 2..23    tier payload, zero-padded to the full 22 bytes
```

Zero-padding is mandatory and must happen **before** encryption. Padding after
encryption would leave the true length visible in the ciphertext structure.

### 3.3 Tier 1 — the composed record

```
 bytes 2..3    u16  intent symbol id
 bytes 4..5    u16  sequence number (replay window, §5.3)
 bytes 6..23   9 x u16 slots, each packed:
                 bits 15..11   role id      (5 bits, 32 roles)
                 bits 10..0    filler id    (11 bits, 2048 symbols)
               a slot of 0x0000 is absent, not "role 0 filler 0"
```

Nine slots, thirty-two roles, a 2048-symbol filler space. The receiver rebuilds

$$M = \rho^1\phi(\text{intent}) + \sum_{k} \rho^{k+2}\big(\phi(\text{role}_k) \oplus \phi(\text{filler}_k)\big)$$

from the ids alone (P3), using the shared domain seed. Note the **permutation per
slot**: without it the record is a commutative XOR heap and role order is lost —
this is the same defect as E6 in the master errata, and it is just as fatal here
as it was in the reasoning engine.

**P4 in practice:** iterate the *receiver's* known role table and unbind only
those. A role id the receiver has never heard of is simply never queried, so an
old unit ignores a field a new unit added, with no version negotiation anywhere
in the protocol. This is the cheapest forward compatibility mechanism available
and it costs exactly zero bytes.

### 3.4 Tier 0 — the glyph

Tier 1 with zero slots. There is no separate format, because a glyph *is* a
composed record with an empty slot list — the padding makes them identical on
air, which is the point of P1.

### 3.5 Tier 0.5 — the sketch

```
 bytes 0..31   256-bit subsampled sketch of the symbol's dense code,
               XORed with a ChaCha20 keystream. No header, no tag.
 bytes 32..33  (none — the 2 B address occupies 0..1 on air)
```

Radio configuration differs and the differences are the whole mechanism:

| Parameter | Value | Why |
|---|---|---|
| Header | **implicit** | an explicit header has its own CRC; a corrupt header drops the frame before the payload is ever seen |
| Payload CRC | **off** | a CRC turns a recoverable frame into a discarded one |
| Length | fixed, known a priori | required by implicit-header mode |

Decode: XOR the keystream, subsample-compare against every lexicon sketch, take
the nearest neighbour, and accept only above the derived threshold
(01-ALGEBRA §5). Garbage resolves to nothing, so **the nearest-neighbour decode
is itself the integrity check** — which is what has to replace the MAC.

**The honest sizing of the prize.** The measured 100%-at-25%-BER figure
(`test_algebra` T8) is the *algebra's* robustness, not the system's. The SX1262
does not hand up graded bit errors; it delivers a payload or drops it. The only
gate you remove by disabling the header and CRC is packet validation, leaving
**preamble detection**, which works roughly **2–4 dB** below decode threshold. In
the d⁴ regime 4 dB is about +25% distance. That 2–4 dB — not the 25% BER number —
is the real prize, and Phase 2 exists to measure whether it is 2, 4, or zero.

**Where it genuinely wins, and only there:** broadcast with no possible ACK. A
beacon to unknown listeners has nobody to negotiate a retransmission with. For
addressed traffic, sending a 34 B frame twice costs the same airtime and buys
~3 dB of selection diversity, so Tier 0.5 is close to break-even. Ship it for
broadcast; treat it as a research track everywhere else.

### 3.6 Tier 2 — voice

Codec2 700C, 4-second clip = 350 B, split into two 168 B fragments, each AEAD'd
independently so one lost fragment does not destroy the other. SF7 only: 178 B at
SF8 is 502 ms and violates P2.

Fragment header occupies the first plaintext byte: `frag:2 | total:2 | rsv:4`.

### 3.7 SOS

```
 bytes 0..1    u16  glyph id (always SOS)
 bytes 2..9    lat/lon, 4 B each, fixed point
 bytes 10..13  u32  key id (truncated hash of the Vault public key)
 bytes 14..15  u16  monotonic counter from the ATECC
 bytes 16..79  ECDSA P-256 signature over bytes 0..15
```

Plaintext and signed, never encrypted — the entire point is that a **stranger**
can verify and relay it. SF8, 82 B, 256.5 ms. This is the one place the privacy
model is deliberately inverted, and it must be surfaced in the UI, not only here.

## 4. Cryptography

### 4.1 Key schedule

```
ATECC608A P-256 keypair, generated on-device at first boot, slot non-readable
        │
        ├── ECDH with peer ──▶ shared secret ──▶ HKDF-SHA256 ──▶ root key
        │                                                          │
        │                                          Double Ratchet chain keys
        │                                                          │
        │                            ┌─────────────────────────────┤
        │                            ▼                             ▼
        │                     message key (32 B)          address key (16 B)
        │                            │                             │
        │                    ChaCha20-Poly1305              first 2 bytes = §4.3
        │
        └── ECDSA ──▶ SOS signatures, pairing SAS, attestation
```

The identity scalar never leaves the ATECC. The ratchet itself runs in software
on the MCU — be precise about this in any security claim: hardware protects
*identity*, not session state. Signal's construction is curve-agnostic, so P-256
ECDH is fine; ~50–100 ms per operation is irrelevant for messaging.

Ratchet state at rest is stored in NVS **wrapped by a key derived inside the
ATECC**, so a flash dump alone does not yield session state.

### 4.2 Nonces are derived, never transmitted

The nonce is `HKDF(chain_key, "nonce" ‖ counter)`. Both ends track the counter,
so it costs zero bytes on air. On a gap, the receiver tries a window of the next
N counters (N = 32 is ample for a lossy link) and then requests a re-key.

### 4.3 Ephemeral addresses

`addr = HKDF(chain_key, "addr" ‖ counter)[0:2]`

The receiver precomputes the next 32 expected addresses per session — 64 bytes
of table — and filters on them **before attempting decryption**. This gives cheap
rejection of foreign traffic without leaking a stable identifier (P6).

Two bytes will collide across a large mesh. That is fine and intended: a
collision costs one wasted decryption attempt, and ambiguity is a *feature* for
traffic analysis resistance.

### 4.4 What is still visible to an observer

Stated plainly, because a security document that only lists defences is
marketing:

| Visible | Mitigation | Residual |
|---|---|---|
| That a transmission happened, and when | none possible | full |
| Its length | P1 makes all meaning-tiers identical | Tier 2 remains distinguishable as "voice was sent" |
| Approximate location | none possible with RF | direction-finding remains feasible for a resourced adversary |
| Traffic volume per area | beacon-slot dummy traffic | reduced, not eliminated |

Tier 2's distinguishability is not fixable by padding — a 178 B frame cannot be
made to look like a 34 B one without spending 5× the airtime and energy. So the
guidance is behavioural, and it belongs in the manual: **if the fact that you
transmitted speech at all must be hidden, do not transmit speech.**

## 5. Weave — the mesh

### 5.1 Energy-aware roles

A node that sleeps 99% of the time is a bad relay; continuous receive costs
127.68 mAh/day against a 19.46 mAh/day capsule harvest. The resolution is that a
mesh does not need every node to route, only *enough* nodes.

| Role | Duty | Cost | Entered when |
|---|---|---|---|
| **Leaf** | 20 ms RX every 2 s | 1.78 mAh/day | default |
| **Responsive** | 20 ms RX every 0.5 s | 5.60 mAh/day | traffic in the last 60 s |
| **Relay** | continuous RX | 127.68 mAh/day | on charger, OR SoC > 80% AND harvest > 10 mW |

The role is advertised in the beacon, so routing follows energy rather than a
hand-set configuration flag. A Band with 20 cm² of cell makes a node
relay-capable; a leather Band makes it a leaf. **The user's strap choice is a
routing decision** — which is what makes the modular Band an engineering feature
rather than a fashion one.

### 5.2 Forwarding

- `ttl` starts at 3 and decrements per hop. Zero is dropped. It lives in the top
  two bits of the on-air header, not in the plaintext — see erratum E-P2 in §3.1,
  without which a relay cannot decrement anything.
- Dedup on `FNV-1a(masked address ‖ ciphertext ‖ tag)` in a 256-entry ring — not on
  `(addr, seq)`, which a relay cannot read (E-P2). This is *not* a stable origin
  id: the fingerprint changes with every message, so it identifies a frame without
  identifying a sender.
- Store-and-forward queue with a per-frame deadline. Expired frames are dropped
  silently, never retried indefinitely.
- Forwarding is **opportunistic and unacknowledged**. A relay can always drop a
  frame, and no protocol change fixes that; end-to-end ACK with a deadline and
  tier fallback is the answer, at the application layer.

### 5.3 Replay

The ratchet advances per message and **every message key is single use** — derived,
used, and destroyed, either by the chain advancing past it or by dropping its
skipped-key cache entry on success. A replayed frame therefore has no key left
anywhere in the system to open it. Verified in `test_net` S2: 24 replays of 8
frames, zero accepted.

> **Revision 0.3 correction.** Revision 0.2 listed a third defence, a receiver-side
> sequence window, for the AEAD tiers. It is redundant there — key deletion is
> strictly stronger, since it also gives forward secrecy — and `firmware/net/session.c`
> deliberately does not have one. Shipping redundant security machinery is worse
> than shipping none: it never executes, so it is never tested, and it invites the
> belief that it is doing something.
>
> A sequence window **is** required for the SOS tier, which is plaintext, signed,
> and has no ratchet to consume: a captured beacon can be re-transmitted verbatim
> and nothing about the signature says "again". `herus_replay` exists for that path,
> with the ATECC's monotonic counter as its source of truth.

## 6. Beat — slotted rendezvous

### 6.1 Why

Duty-cycled listening trades latency for power. A 2 s window means up to 2 s of
delay. Beat recovers most of it by making the windows *agree*: all nodes in a
group open their receiver on a common 2 s boundary derived from a shared epoch,
so a transmitter that also aligns hits a listening receiver on the first try.

The radio does this without host involvement. `SX1262 SetRxDutyCycle` alternates
RX and sleep autonomously and interrupts the MCU only on preamble detection, so
the ESP32 sleeps at 15 µA through every empty window. Waking the MCU 43 200
times a day merely to run CAD would cost ~1.8 mAh/day on its own — more than the
radio it was trying to help.

### 6.2 Timing, derived

| Quantity | Value |
|---|---|
| Crystal tolerance | ±20 ppm each end |
| Relative drift | 40 µs/s |
| Drift over a 60 s resync interval | 2.40 ms |
| Guard window | ±10 ms (4× the drift) |
| SF9 symbol | 4.096 ms |
| 8-symbol preamble | 32.8 ms |
| RX window | 20 ms = 4.9 symbols |
| **Preamble ≥ 2 × guard?** | **yes, 32.8 ≥ 20** |

The standard 8-symbol preamble already covers the guard window, so **no
long-preamble mode is needed and no extra airtime is spent.** This is a
convenient accident of SF9's symbol duration and it should be re-derived if the
spreading factor ever changes.

Resync: every frame carries an implicit time reference in its arrival instant.
Any successfully decoded frame from a node with a better clock class re-anchors
the local slot phase. Clock class is 2 bits of the beacon.

## 7. Region profiles

First-class, compiled in, selected at provisioning. Never inferred at runtime
from anything an attacker can influence.

| Profile | Band | Max SF (34 B) | Dwell / duty | Notes |
|---|---|---|---|---|
| **BR915** | 902–907.5, 915–928 MHz | 9 | 400 ms dwell | ANATEL Ato 14448; product needs homologação |
| **US915** | 902–928 MHz | 9 | 400 ms dwell | FCC 15.247(a)(1)(iii), ≥50 hop channels |
| **EU868** | 863–870 MHz | 9 | **1% duty** | ~145 frames/hour at 246.8 ms — fine for messaging, fatal for calls |
| `LAB` | — | 12 | none | **default-disabled.** Requires an experimental or licensed basis. Exists so research is possible without shipping an illegal device |

SF10–12 are absent from every shipping profile. Every LoRa range figure quoted at
SF12 — including most of the folklore around comparable projects — describes a
transmission that exceeds the dwell limit.

## 8. Implementer footguns

Collected because each one has a plausible-looking wrong answer.

1. **Do not pad after encrypting.** Pad the plaintext to 22 bytes first.
2. **Do not enable CRC on Tier 0.5.** It converts its only advantage into its
   normal failure mode.
3. **Do not use AEAD on Tier 0.5.** Poly1305 avalanches; one bit error destroys
   the frame, which is precisely what this tier exists to avoid.
4. **Do not reuse a nonce across the ratchet step.** Derive from the chain key
   *and* the counter.
5. **Do not treat slot value `0x0000` as "role 0, filler 0".** It means absent.
6. **Do not skip the permutation per slot.** Without ρ^(k+2) the record is a
   commutative heap and role order is silently lost (master errata E6).
7. **Do not let voice authorise anything.** Voice biometrics is a wake gate; the
   button and the ATECC are the authority.
8. **Do not ship without the eFuse ritual** — flash encryption, secure boot v2,
   JTAG disabled, UART download disabled. Until those four are burned, "the key
   never leaves the chip" is true and irrelevant, because the *session* keys are
   sitting in readable RAM.
9. **Do not rate-unlimited the decrypt path.** The 64-bit truncated tag assumes
   an attempt limit.
10. **Do not infer the region profile at runtime.** Compile it in.

## 9. Reproduce

```bash
./prove.sh                       # all four suites and 26 invariants
python3 tools/budget.py          # §8 frame ledger, §9 ranges, §10 Beat timing
cd firmware && make net          # P1-P8 of this document, as tests that can fail
```

If the frame ledger's assertion fires, P1 has regressed. If any airtime in §2
exceeds 400 ms, P2 has regressed. Both are build failures, not warnings.
