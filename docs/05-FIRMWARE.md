# 05 — Firmware

**Revision 1.0 · the definitive build · everything here is verified by `./prove.sh`**

This is the document you work from at the bench. It says what exists, what it is
proven to do, what it deliberately does not do yet, and the exact sequence from an
unopened board to a meaning crossing a street.

Companions: [02-PROTOCOL.md](02-PROTOCOL.md) for the wire contract,
[03-BUILD-GUIDE.md](03-BUILD-GUIDE.md) for the phase plan and its kill criteria.

## 1. The shape of it

```
firmware/
  core/      the algebra — portable, no I/O, no allocation on the hot path
    hv.[ch]        dense binary VSA (MAP-B): bind = XOR, bundle = majority, permute = rotate
    sbc.[ch]       sparse block codes: the second algebra, 10x smaller, no popcount needed
    lexicon.[ch]   derived codebook, learned prototypes with a drift guard, resonator
    hcp.[ch]       Herus Composition Protocol rev 0.2 — meaning <-> 24 bytes
    nucleus.[ch]   Nucleus: opt-in, bounded semantic transition memory
    voice.[ch]     Voice: controlled PT parsing and bounded haptic plans
    interaction.[ch] Runtime: push-to-talk, confirmation and one-shot handoff
    interaction_rig.[ch] Lab: deterministic adapter sequencing and measured-energy handoff
  net/       the wire — portable, no radio, testable on a Mac
    crypto.[ch]    SHA-256, HMAC, HKDF, ChaCha20, Poly1305, AEAD. Nothing else.
    session.[ch]   symmetric ratchet, ephemeral addresses, skipped keys, rate limit
    region.[ch]    airtime, dwell and region profiles — as COMPILE-TIME assertions
    weave.[ch]     dedup, hop limiting, store-and-forward deadlines, energy roles
    beat.[ch]      slotted rendezvous: the schedule, the guard, the resync
    link.[ch]      the two calls an application makes: link_send, link_recv
  port/      the platform — eight functions and a radio
    hal.h                  the entire platform contract
    sx1262.[ch]            the radio driver, over a 4-function bus abstraction
    esp32s3/board_t3s3.h   >>> THE ONE FILE TO EDIT IF YOUR HARDWARE DIFFERS <<<
    esp32s3/hal_esp32s3.c  SPI, GPIO, NVS, sleep, RNG
    esp32s3/main/app_main.c bring-up console and radio task
  test/      the proofs
    test_net.c     P1-P8, S1-S5, W1-W2, B1-B2, C1, X1
    test_radio.c   R0-R10 against a recording mock bus — no hardware needed
    vectors.h      crypto vectors generated by an INDEPENDENT implementation
    idf_stub/      fake ESP-IDF headers, so the app type-checks on a Mac
  ranger/      the Phase-0 Arduino range probe (RadioLib). Unchanged, still correct.
```

The line between `core`/`net` and `port` is the whole reason Phase 1 is debuggable
on a laptop. Above it: 4 200 lines that run identically on a Mac and an ESP32-S3.
Below it: eight functions and a radio.

## 2. What is proven, and by what

`./prove.sh` runs twenty-one suites and gates 51 proof invariants. It exits non-zero if any
one of them regresses, and it is the only thing standing between you and a
plausible-looking bug in a device you will trust with an emergency.

| Suite | What it proves | How |
|---|---|---|
| **algebra** | quasi-orthogonality vs closed form, exact invertibility, bundle capacity, resonator convergence, learning with an enforced separation floor, 9-slot HCP round trip | measurement next to theory |
| **Nucleus** | consentimento opt-in, memória com capacidade fixa, confiança explícita, supressão de auto-sugestão, expiração e apagamento local | testes determinísticos sem I/O, alocação, rádio ou rede |
| **voice** | interpretação local de português controlado, rascunho confirmável, SOS bloqueado e planos hápticos limitados | testes determinísticos sem microfone, ASR, rádio, GPIO ou driver de vibração |
| **intent gateway** | sessão física, limiar de confiança, margem de ambiguidade, contexto limitado e rejeição de resultado obsoleto | testes determinísticos sem áudio, transcrição, Núcleo físico, rádio ou transporte |
| **dialogue** | turno físico, fala transitória, cartões tipados, resposta UX apagável e autoridade de transmissão zero | testes determinísticos sem ASR, TTS, LLM, rede, rádio ou armazenamento de transcrição |
| **model lab** | perfil alvo/local identificado, orçamento de recurso, cobertura funcional/adversarial e recusa de rede/agência | testes de política com perfis sintéticos; não é perfil de modelo ou hardware |
| **memory policy** | sessão autorizada, relevância explicável, revisão de conteúdo sensível/de terceiros e nenhuma persistência autônoma | testes determinísticos sem áudio, texto, ASR, LLM, armazenamento ou rede |
| **memory capture** | gesto físico, janela limitada, entrega única, geração anti-buffer-atrasado, expiração, cancelamento e zeroização transitória | testes determinísticos sem microfone, I2S, DMA, AFE/VAD, ASR, LLM, armazenamento ou rádio |
| **memory extract** | gramática local limitada, candidato tipado, origem/confiança, risco de terceiros/sensível e nenhuma retenção textual | testes determinísticos sem ASR real, LLM, cofre, diálogo, HCP, rede ou rádio |
| **memory vault** | autorização humana separada, cartão mínimo sem texto, HKDF por domínio/geração, AEAD de tag completa, piso anti-rollback e erase fail-closed | testes determinísticos com backend RAM host; não prova NVS cifrado, eFuse, secure element, atomicidade de flash ou resistência física |
| **assurance** | composição fail-closed de PTT, intenção, confirmação, trust, frescor, revogação e fronteira de modelo | testes determinísticos sem criar HCP, pacote, link ou rádio |
| **capstone** | cadeia diálogo→modelo→interação→trust, precedência de revogação e handoff único | testes de módulos portáveis; não representa BLE, ASR, LLM ou energia física |
| **trust lifecycle** | associação física dupla, SAS, derivação, persistência opaca, revogação e zeroização | testes determinísticos sem BLE real, secure element, RNG alvo ou backend persistente |
| **control link** | AEAD de tag completa, vínculo de par, direção, sequência, expiração, replay e entrega limitada de observação do Núcleo | testes determinísticos sem BLE, secure element, armazenamento persistente ou chave de produção |
| **interaction** | push-to-talk, prazo, perda de fonte, confirmação, handoff de uso único e telemetria sem fala | testes determinísticos sem microfone, ASR, rádio, GPIO, chave ou relógio de sistema |
| **validation lab** | rig de adaptadores, sequência de captura/apresentação/háptica, handoff único e rejeição de logs inseguros | testes determinísticos em host; não representa uma medição física |
| **readiness manifest** | schema de gates, privacidade de logs e aprovação somente com arquivo de evidência | valida o plano de bancada; não cria uma medição ou aprova gate físico |
| **preregistered study** | plano congelado, balanceamento, intervalos de Wilson, gates H1–H5 e rejeição de dados inseguros | testes de método com fixtures; não representa resultado de participantes ou hardware |
| **protocol** | crypto correctness, forward secrecy, replay, forgery, rate limiting, out-of-order recovery, forward compatibility, canonical encoding, flood termination, Beat drift | 50 random cases per primitive against OpenSSL, plus adversarial cases |
| **radio** | command ordering, frequency word, PA table coherence, sync word, BUSY discipline, duty-cycle arithmetic, and that the selftest diagnoses each plausible bring-up fault | a recording mock bus |
| **physical** | airtime, dwell, range, energy, frame ledger | `tools/budget.py` |

Two of those deserve naming explicitly.

**The crypto is differentially tested, not asserted.** Hand-rolled crypto fails
through implementation error. So `tools/gen_vectors.py` asks Python's
`cryptography` (OpenSSL underneath) for the answer on 50 random inputs per
primitive, and `test_net` V1–V6 checks every one. 300 cases, zero mismatches. If
`crypto.c` and OpenSSL ever disagree on random input, the build fails.

**The radio driver is verified without a radio.** `test_radio.c` plugs a recording
mock into `sx_bus_t` and asserts the things that are ordering-sensitive in the
datasheet and silent when wrong — `SetPacketType` before `SetModulationParams`,
`0x39300000` for 915 MHz, PA config and TX power from the same table row, the
private sync word, BUSY before every command, and 1280/128000 steps for a
20 ms/2 s duty cycle. **A bench afternoon is for antennas, not opcodes.**

## 3. Two errata found while building this

Both were found by writing the code that had to obey the documents. Both are
fixed in the firmware, in `budget.py`, and in the documents themselves.

### E-P1 — P1 was about bytes when it should have been about airtime

Revision 0.2 gave Tier 0.5 the same **34 bytes** as Tier 0/1 and concluded the
tiers were indistinguishable. They were not. Tier 0.5 runs implicit header with
CRC off — 36 fewer bits in the symbol count — so 34 B costs **226.3 ms** against
**246.8 ms**. A 20.5 ms difference, visible to exactly the spectrum analyser P1
exists to defeat, and eight times the Beat guard window.

Worse, `budget.py` asserted `len(Tier0) == len(Tier0.5)` and **passed**, while the
invariant it was named after was broken. That is the most expensive kind of test:
one that provides confidence without providing coverage.

**Fix.** At SF9 the payload symbol count is a step function; 36–39 bytes of
implicit-header CRC-less payload all land on exactly 48 symbols. Tier 0.5 becomes
**38 bytes** — 2 address + 32 sketch + 4 pad — and the airtime is identical. The
4 pad bytes are a free sketch extension to 288 or 320 bits for a later revision,
because the step does not move until 40 bytes. The assertion is now on airtime,
in `budget.py` and as a `_Static_assert` in `region.c`.

### E-P2 — Weave, as specified, could not be implemented

§3.2 puts `ttl` in the plaintext header. §5.2 has each relay decrement it and
dedup on `(ephemeral_addr, seq)`. Those cannot both be true: the plaintext is
inside the end-to-end AEAD, so a relay can read neither `ttl` nor `seq`.

**Fix.** Two bits of the on-air address become the hop counter:

```
 bits 15..14  ttl       public, mutable, NOT authenticated
 bits 13..0   address   public, authenticated via the AEAD's AAD
```

- The address space drops to 16384, so collisions get 4× more likely. The protocol
  already declares collisions acceptable and useful; the cost is one wasted
  decrypt attempt, which the rate limiter bounds.
- `ttl` is malleable. Raising it cannot amplify a flood, because dedup makes each
  node forward a frame at most once regardless. Lowering it suppresses forwarding,
  which the threat model already concedes and which jamming achieves anyway.
- Touching the address bits breaks the tag. Proven in `test_net` P8.
- Dedup keys on `(address with ttl masked, ciphertext, tag)` — a 32-bit FNV-1a over
  what a relay can actually see. The tag is a 64-bit function of the whole message
  under a key the relay does not have, which makes it a far better duplicate
  discriminator than a 16-bit sequence number.

**Masking the ttl in the dedup key is load-bearing:** the same frame arriving at
ttl 3 and at ttl 2 must be recognised as one frame, or the flood never terminates.

## 4. What this firmware does NOT do yet

Stated plainly, because a firmware document that only lists features is a brochure.

| Missing | Consequence today | Where it lands |
|---|---|---|
| **ATECC608A: no ECDH, no ECDSA** | Sessions start from a pre-shared root key. You get **forward secrecy** — yesterday's messages stay unreadable — but **not post-compromise security** in the field, and **no SOS signing**. `session_dh_ratchet()` is written and tested; it needs a shared secret from the secure element to be called. Say "forward secrecy", never "Signal-grade". | Phase 4 |
| **Deep sleep** | `hal_sleep_until_radio()` uses light sleep, ~240 µA, not the 15 µA the 1.78 mAh/day leaf budget assumes. Deep sleep loses RAM, and the ratchet lives in RAM, so this needs NVS persistence wrapped by an ATECC key first. **Quote the light-sleep number until Phase 3 measures the other one.** | Phase 3–4 |
| **Tier 2 voice (Codec2)** | No push-to-talk. `region.c` already asserts its airtime is legal at SF7. | Phase 1, and only if the street recording is intelligible |
| **Echo (symbol → audio)** | Received meanings print on the console instead of speaking. | Phase 2 |
| **Tier 0.5 receive path** | The app transmits sketch beacons; decoding them means `lex_search_sketch()` on a frame received in implicit/CRC-off mode. All the pieces exist and are tested; the app does not wire them together. | Phase 2, alongside the 2–4 dB falsification test |
| **Nucleus hardware integration** | `nucleus.[ch]` proves local learning constraints on host only. The Core↔Nucleus encrypted link, power domain, charger, antenna and UI confirmation have not yet been wired to hardware. | Nucleus-0 onward; see [06-NUCLEO.md](06-NUCLEO.md) |
| **Voice/haptic hardware integration** | `voice.[ch]` proves parsing, confirmation and vibration bounds on host only. Button-gated microphone, local ASR, audio front-end, confirmation UX and ERM/LRA driver are not yet wired. | Advance 1 hardware track; see [07-VOZ-HAPTICA.md](07-VOZ-HAPTICA.md) |
| **Interaction hardware integration** | `interaction.[ch]` proves the event state machine on host only. ESP-SR adapter, Core↔Nucleus transport, actual button wiring, hardware clock and call into `link_send` remain ports above the runtime. | Advance 2 hardware track; see [08-RUNTIME-INTERACAO.md](08-RUNTIME-INTERACAO.md) |
| **Intent gateway hardware adapter** | `intent_gate.[ch]` proves session/confidence policy only. Mapping ESP-SR command IDs and confidence fields, obtaining authorized Nucleus hints and carrying the session over an encrypted local link remain target adapters. | Advance 5 integration track; see [11-GATEWAY-CONFIANCA.md](11-GATEWAY-CONFIANCA.md) |
| **Core↔Nucleus control transport** | `core_link.[ch]` proves application-envelope authentication, sequence and expiry only. LE Secure Connections/OOB association, protected `pair_key`, persistent anti-replay state, BLE GATT and clock source remain target ports. | Advance 6 integration track; see [12-ENLACE-CORE-NUCLEO.md](12-ENLACE-CORE-NUCLEO.md) |
| **Physical validation** | `interaction_rig.[ch]` and `tools/interactionlog.py` prove scenario sequencing and log gates only. A/B source choice, intent accuracy, false-draft rate, latency and energy still require a pre-registered hardware run. | Advance 3 lab track; see [09-VALIDACAO-FISICA.md](09-VALIDACAO-FISICA.md) |
| **Confirmatory study** | `studyplan.py` and `interactionstudy.py` freeze and analyze the A4 protocol only. The fixture test validates the analyzer; it is not participant or hardware evidence. | Advance 4 research track; see [10-INVESTIGACAO-PREREGISTRADA.md](10-INVESTIGACAO-PREREGISTRADA.md) |
| **Ratchet state persistence** | A reboot loses the session; re-pair. | Phase 4 |
| **Memory-vault target backend** | `memory_vault.[ch]` prova formato cifrado, chave por geração e bloqueio em falha com uma porta RAM. Raiz protegida, NVS cifrada, piso monotônico durável, recuperação após power-loss e erase físico ainda não foram integrados nem medidos. | Phase 4; ver [20-COFRE-MEMORIA.md](20-COFRE-MEMORIA.md) |
| **eFuse ritual** | Until flash encryption, secure boot, JTAG-off and UART-download-off are burned, session keys sit in readable RAM and "the key never leaves the chip" is true and irrelevant. | Phase 4, one-way, sacrificial board first |

## 5. Measured cost

Host (this Mac, one core), and the projection onto the target. The projection is
scaled from the on-target `selftest` timings — run it and replace these numbers
with what your board actually reports.

| Operation | Host | Why it does not matter |
|---|---|---|
| `link_send` + `link_recv`, full round trip | **15.8 µs** | the frame it protects occupies the air for **246 800 µs** |
| seal or open, one direction | ~8 µs | 15 000× less than the airtime |
| address window slide, per accepted frame | 2 HMACs | it was 64 before the frontier chain; a 30× saving on the hot path |

**RAM, measured by `sizeof`:**

```
session state, per peer   1880 B      (32 addresses + 32 skipped keys + 2 chains)
weave                     1512 B      (256 fingerprints + 8 queued frames)
beat                        24 B
lexicon sketch table     16384 B      (512 symbols x 32 B) — the only table
hv_acc_t scratch         20480 B      caller-owned, one at a time
codebook                     0 B      derived from (domain, id) on demand
```

Total working set ≈ **40 KB**, against 512 KB of internal SRAM with IDF and the
radio stack taking 150–250 KB. The 72 KB cognition budget in
[03-BUILD-GUIDE.md](03-BUILD-GUIDE.md) Phase 2 still fits, with room.

## 6. From an unopened board to a meaning crossing a street

### 6.1 Prove it on the Mac first (two minutes, no hardware)

```bash
cd ~/Python/herus && ./prove.sh
```

Everything must be green. If it is not, stop — the bug is here, where it is cheap,
not on the bench, where it is not.

### 6.2 Install ESP-IDF (once, ~20 minutes)

```bash
mkdir -p ~/esp && cd ~/esp && git clone -b v5.3 --recursive https://github.com/espressif/esp-idf.git && ~/esp/esp-idf/install.sh esp32s3
```

Then in every new shell: `. ~/esp/esp-idf/export.sh`

### 6.3 Verify the pin map (ninety seconds, and it saves an afternoon)

Open `firmware/port/esp32s3/board_t3s3.h`. Compare the six SX1262 pins against the
schematic for **your** board revision. LilyGO has shipped several T3-S3 pinouts
under one name, and a wrong `BUSY` or `DIO1` looks exactly like a dead radio.

### 6.4 Build and flash

```bash
cd ~/Python/herus/firmware/port/esp32s3 && idf.py set-target esp32s3 && idf.py build flash monitor
```

### 6.5 The first five commands

```
selftest
```
Four checks in order: SPI round trip, oscillator and calibration, chip status,
receiver noise floor. Each failure names the cause and the fix — a wrong pin map
names `board_t3s3.h`, a TCXO problem names `BOARD_HAS_TCXO`. It also prints
`hv_gen` and `hv_dist` timings on the real core, which is how the projections in
[00-HERUS-MASTER.md](00-HERUS-MASTER.md) §11 stop being projections.

```
lexcheck
```
Prints a fingerprint of the first 64 derived codes. **It must be byte-identical on
both boards.** This is the cheapest possible confirmation of the entire
"derived, never transmitted" thesis: two devices, one 64-bit seed, the same
codebook, and nothing sent.

```
pair demo a        (on board A)
pair demo b        (on board B)
```
A development key that is printed in the source. The console says so every time,
because a user who believes a demo key is private has been misled by us.

```
listen             (on board B)
send 41 1:7 3:300  (on board A)
```
Board B prints the intent and the named slots. That is a meaning crossing the air
in 34 bytes and 246.8 ms.

```
range 200
```
200 frames at a strict 2.000 s cadence for the Phase-0 walk. Start a stopwatch,
note the time at each distance mark, and feed both logs to `tools/fieldlog.py`.
Elapsed time is the distance record — no GPS, no display, nothing else to fail.

Also useful: `beat` (duty-cycled receive; put the power analyser on it), `sketch 7`
(a Tier 0.5 beacon), `stats` (session, Weave, Beat and radio counters), `idle`.

## 7. Porting to the Phase-4 PCB

Change `board_t3s3.h`, and nothing else:

- the six SX1262 pins;
- `BOARD_TX_DBM` → **14** if the antenna is capsule-internal. At −8 dBi realised
  gain, +22 dBm heats your wrist rather than radiating;
- `BOARD_HAS_TCXO` to match the module you actually bought;
- put `PIN_LORA_BUSY` on an RTC-capable GPIO if the radio should ever wake the MCU
  through BUSY rather than DIO1.

Then, before trusting any range measurement, run `selftest` and compare the noise
floor against the devkit baseline. A 6 dB difference there is an antenna problem,
and it is much cheaper to find at the bench than on a walk.
